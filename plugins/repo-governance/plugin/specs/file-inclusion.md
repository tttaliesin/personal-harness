# K7 파일 포함과 제외

파일을 누가 어떤 목적으로 읽거나 유지하는지 확인해 저장 위치를 제안한다.
제품 버전을 만들거나 사용하고 재현하는 데 필요한 원본은 해당 저장소에 둔다.
개인 작업 자료와 실행 결과는 실제로 Git에서 제외되는 로컬 위치나 저장소 밖에 둔다.

## 용도와 위치

| 용도 | 권하는 보관 위치 |
| --- | --- |
| 소스·설정·현행 명세·사용 설명처럼 제품 책임을 설명하거나 수행하는 원본 | 실제 소비 경로와 같은 저장소의 제품 영역. 새 원본은 확인한 제품 요구로 편입 근거를 설명할 수 있다. |
| 재현 가능한 테스트 소스와 fixture | 테스트가 실제로 읽는 경로. 테스트 전용 자료와 설치하는 파일을 디렉터리와 배포 규칙에서 구분한다. |
| 다른 제품이 쓰는 공통 스킬·검사·템플릿의 원본 | 유지하는 공통 저장소. 필요한 제품별 연결과 입력은 해당 제품에 최소한으로 둔다. |
| 개인 색인·조사 초안·원시 로그·실행 결과 | 사용자 로컬 제외 경로나 공유하기로 한 외부 작업 공간. 재생성하거나 보관할 범위를 함께 고려한다. |
| 제품 계약과 개인 상태가 섞인 파일 | 현재 유지할 계약과 개인 작업 부분을 나눠 각각의 장소에 둔다. |
| 실제 용도를 알 수 없는 자료 | 임시로 로컬에 두고 편입 전에 소비 경로와 유지 책임을 확인한다. |

이 저장소의 `tests/cases/mechanical.json`은 테스트가 입력으로 읽는 원본이다.
`.codegraph/`와 `.audit/`는 로컬 작업 자료로 제외 설정에 들어 있다.
다른 저장소에서 이름이 같은 파일은 실제 사용처와 책임으로 판단한다.

### 설치·배포 범위와 파일 배치

설치나 패키징이 바뀌면 의도한 파일과 실제 포함 범위를 대조한다.
이 저장소는 설치할 리소스를 `plugin/`에 두고, 테스트와 검증 자료를 개발 영역에 둔다.
필요한 실행 원본은 소비 경로와 함께 배포한다.
일회성 검증 기록과 무관한 산출물은 실행 배포물의 범위에서 제외한다.
Git에 남길 테스트 fixture도 패키지에 포함할 이유를 별도로 확인한다.

## 생성과 편입

파일을 만들기 전에 확인할 수 있는 출력 목적과 위치를 파악한다.
개인 한정 제외가 필요하면 로컬 exclude를 사용할 수 있다.
팀 공통으로 재생성하는 결과라면 해당 저장소의 추적 제외 기준을 확인한다.
추적한 파일은 ignore를 추가해도 후보에 남으므로 실제 Git 상태를 확인한다. [Git 제외 규칙](https://git-scm.com/docs/gitignore)

일반 미추적·ignored 파일은 그 상태만으로 생성이 막히지 않는다.
명시한 제품 출력 경계가 있으면 지원 훅이 생성 시 추적 파일과의 충돌·유효한 Git 제외·실제 경로를 확인한다.
출력이 제품 원본을 덮어쓸 가능성을 알게 되면 다른 위치를 먼저 제안한다.
산출물의 용도와 내용을 알 수 없는 생성은 허용된 임시 위치에서 실행할 수 있는지 확인한다.
에이전트는 생성 결과 중 유지할 원본이 생기면 내용과 소비 경로를 보고 편입을 판단한다.

지원하는 커밋에서는 실제 포함 후보를 확인한다.
선언한 로컬 전용 출력이 후보에 포함되면 훅이 거절한다.
에이전트가 혼합 파일이나 용도 미확인 파일을 후보에서 발견하면 해당 편입을 보류하고 필요한 확인만 요청한다.
새 변경과 무관한 과거 자료를 자동으로 옮기거나 삭제할 필요는 없다.
출력을 어디에 둘지 묻는 요청에는 위치와 근거를 제시한다.
