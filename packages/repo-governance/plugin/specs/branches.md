# K5 브랜치 이름

브랜치 목록에서 작업을 식별하도록 짧은 영문 소문자 케밥 케이스를 권한다.
현재 작업의 대상과 행동으로 이름을 짓는다.
`update-setup-guide`는 설정 안내서를 갱신하는 작업을 가리킨다.
해당 작업을 찾는 데 도움이 되면 실제 이슈 번호를 `123-prevent-expired-token-reuse`처럼 넣을 수 있다.

## 이름과 기준

`prevent-expired-token-reuse`, `document-local-setup`처럼 작업을 식별할 수 있게 쓴다.
`temp`나 `work`처럼 작업을 알 수 없는 이름을 보완한다.
Git에서 허용하는 이름과 현재 저장소의 권고 형식은 각각 확인한다. [Git ref 이름 조건](https://git-scm.com/docs/git-check-ref-format)

새 브랜치를 만드는 경우 사용자가 뜻한 기준 ref를 찾아 현재 커밋으로 해석한다.
후속 PR이면 선행 브랜치가 실제 기준인지 확인한다.
동명 브랜치가 있으면 같은 작업인지와 어느 worktree에서 쓰는지 확인하고 재사용을 먼저 제안한다.
다른 작업의 ref를 덮어쓰려면 별도 요청이 필요하다.
기존 브랜치 선택에 새 이름 규칙을 소급하지 않는다.

호스트나 기존 자동화가 특정 접두어를 실제로 부여하거나 요구하면 해당 자료를 확인한다.
유효한 제품 설정이 선언한 접두어를 그대로 쓰고 그 뒤에는 작업 이름을 붙인다.
접두어를 포함한 전체 이름이 유효한 Git ref여야 한다.
선택적 유형 표기로 임의의 `fix/`를 붙이는 대신 실제 작업을 설명하는 이름을 권한다. [공통 예외 기준](../SPEC.md#66-프로필예외와-충돌-처리)

## 만들기 전 확인

지원 훅은 새 이름의 형식·Git ref 유효성·확인할 수 있는 시작점·동명 ref를 검사한다.
에이전트는 그 기준에서 작업해야 하는 이유와 접두어의 실제 필요한 범위를 확인한다.
기존 이름이나 기준 ref가 달라졌으면 현재 후보에서 확인한다.
제안 요청에는 사용할 목적과 기준을 함께 적는다.
