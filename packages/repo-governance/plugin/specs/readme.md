# K3 README

README 첫 부분에서 이 저장소를 누가 무엇에 쓰는지와 첫 행동을 보여준다.
실제 진입점과 설치·사용 문서부터 확인한다.
독자가 시작에 필요한 조건과 따라 했을 때 확인할 결과를 가까이에서 읽을 수 있게 배치한다.

## 시작점 고르기

| 독자가 하려는 일 | 먼저 보여줄 내용 |
| --- | --- |
| 앱이나 API를 사용한다. | 지원하는 실행 또는 접속 방법과 첫 결과. API라면 대표 요청과 응답. |
| CLI를 실행하거나 라이브러리를 호출한다. | 실제 기본 명령이나 사용 코드, 예상 출력이나 반환 값. |
| 플러그인이나 스킬을 도입한다. | 사용할 호스트에서 지원하는 설치·활성화 경로와 설치 후 첫 사용. |
| IaC를 재사용하거나 배포를 운영한다. | 관리하는 환경과 현재 맡은 범위, 입력·적용 영향 중 먼저 확인해야 할 내용. |
| 문서·템플릿·예제를 읽거나 가져다 쓴다. | 바로 읽거나 복사할 자료 링크, 처음 선택할 기준, 적용 결과를 확인할 방법. |

필수 버전·환경 설정·권한·주의점은 실제로 필요한 경로에 적는다.
구성·검증·운영·갱신·문의 안내를 붙일 때는 독자가 이어서 하려는 일을 기준으로 위치를 고른다.
설명이 길면 필요한 위치로 연결한다.
README가 사용 설명서 자체라면 본문에 두고 목차를 고려한다.
기존 README를 수정할 때는 유효한 내용과 독자의 이동 경로를 보존한다.

Dify는 기본 Docker 실행과 초기 설정 화면을 빠른 시작에 두고 상세 설정을 배포 가이드로 연결한다.
nvm은 README에 사용 설명서를 두고 목차로 탐색할 수 있게 한다.
두 사례는 독자가 이어서 할 일이 어디에 있는지에 따라 문서 길이와 배치를 고른다는 근거다. [Dify 빠른 시작](https://github.com/langgenius/dify/blob/main/README.md#quick-start) · [Dify 배포 가이드](https://github.com/langgenius/dify/blob/main/docker/README.md) · [nvm 목차](https://github.com/nvm-sh/nvm/blob/master/README.md#table-of-contents)

## 배치와 예시

[README 템플릿](../templates/README.md)은 바로 시작할 경로를 쓰는 예시다.
확인한 정보로 채워 쓰거나 현재 프로젝트에 맞춰 일부만 사용한다.
제목 문구·정렬·절 구성·이미지·표·목차는 사용 경로에 맞게 선택한다.
시각 자산을 넣으면 실제로 제공하는 것을 보여주고 대체 텍스트를 붙인다.
화면이나 테마 지원 여부를 설명할 때는 확인한 범위를 쓴다.

이 저장소의 소스 체크아웃에 있는 `docs/DESIGN.md`는 `governance-tool` README와 배너의 시각 기준이다.
각 제품에 자체 디자인 문서가 있다면 그 배치와 표현을 적용할 수 있다.
기존 제품 설정의 `readmeProfile`도 배치 선호로 읽을 수 있다.

실제 성공 기록이 없으면 문서의 예상 동작과 확인 상태를 구분한다.
예제 경로나 템플릿 문법은 예제임을 설명해 그대로 쓸 수 있다.
완성할 본문에 남은 작성용 자리표시자는 실제 정보로 바꾼다.
사용자가 확인 실행을 허용한 범위에서 결과를 확인한다.

## 커밋과 원격 반영

로컬에서 초안을 작성하고 저장할 수 있다.
지원하는 커밋에서는 편입할 README의 내용과 상대 링크·앵커를 실제 후보 기준으로 확인한다.
지원하는 원격 README 직접 반영은 변경 직전에 해당 후보를 확인한다.
기계 검사는 읽을 수 있는 후보에서 알려진 작성용 자리표시자와 깨진 내부 링크 등 확정할 수 있는 문제를 다룬다.
에이전트는 명령이 현재 지원되는지, 안내가 정확하고 실제 독자가 시작할 수 있는지 판단한다.
절 이름이나 선택 자산의 유무만으로 차단하지 않는다.
