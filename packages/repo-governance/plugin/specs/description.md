# K2 저장소 설명

목록에서 저장소의 현재 용도를 판단할 수 있도록 짧은 한국어 한 줄을 권한다.
누가 무엇을 하려는 때 이 저장소를 쓰는지 실제 기능과 함께 표현한다.
식별에 도움이 되는 경우에만 제품명·기술명·지원 대상을 넣는다.
끝 마침표는 문체에 따라 선택한다.

## 작성 기준

주문 조회 API라면 `주문 이력과 처리 상태를 조회하는 업무 API`처럼 쓸 수 있다.
개발 도구라면 그 도구로 할 일을 먼저 적는다.
nvm의 설명이 Node.js의 여러 버전을 관리하는 셸 도구임을 밝히는 방식이 그 예다.
한국어로는 `Node.js를 설치하고 사용할 버전을 전환하는 셸 도구`로 설명할 수 있다. [nvm 저장소 설명](https://github.com/nvm-sh/nvm)

실제 진입점이나 자료의 쓰임을 읽고 README와 제공 상태를 대조한다.
현재 공개한 작업이 설계 명세라면 지금 읽을 수 있는 명세가 어떤 계약을 설명하는지 쓴다.
앞으로 구현할 기능이나 확인하지 않은 지원 범위를 현재 상태로 소개하면 수정한다.
기술 목록이나 고객사명만으로 용도를 알기 어렵다면 실제 기능을 넣어 작성한다.
출처가 충돌하면 확인된 범위로 초안을 제시하고 현재 사실을 확인한 뒤 적용한다.

## 검사

새 설명을 쓰는 지원 호출에서 훅은 빈 값·줄바꿈·알려진 자리표시자를 찾는다.
에이전트는 한국어 문장이 자연스럽고 실제 용도가 드러나는지 판단한다.
필요한 정보가 드러나면 짧은 구나 한 문장 모두 사용할 수 있다.
설명을 제안만 요청받았으면 문구와 근거를 제공한다.
