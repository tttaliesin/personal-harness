# Tasks

## 1. 채팅 등록과 운영 위임

- [x] 1.1 `candidate`가 공식 이력에서 현재 채팅을 확인하면 자동 등록한다. 이후 페이지와 `claim`을 생략한 경우, 이력 연결이 끊긴 경우, 프로젝트·호스트 불일치와 워커 호출을 각각 검사한다.
- [x] 1.2 프로젝트 정체성과 채팅별 위임을 함께 저장한다. 두 채팅이 동시에 등록해도 프로젝트 ID는 하나인지, 새 채팅의 권한은 모두 `false`인지, 기존 사용자 위임은 원래 채팅에만 남는지 검사한다.

## 2. 실행 소유권

- [x] 2.1 `dispatch`가 실제 호출자를 `task.controllerRef`에 기록하게 한다. 두 채팅의 독립 배정, 같은 작업에 대한 동시 배정, 후속 배정과 재시도의 소유자를 검사한다.
- [x] 2.2 `status`와 실행 명령에 소유자 검사를 적용한다. 다른 채팅의 작업을 직접 지정하거나 요청에 상대 채팅 ID를 넣어도 작업을 읽거나 변경할 수 없는지 검사한다.
- [x] 2.3 소유자 참조가 없는 이전 실행을 지원한다. 기존 상태에서 원래 컨트롤러가 결과를 확인하고 같은 작업을 이어서 배정할 수 있는지 검사한다.

## 3. 저널과 Desktop 메시지

- [x] 3.1 `push-result`가 등록된 실행에서 수신자를 읽게 한다. 각 워커가 자신을 배정한 채팅의 호출 계획을 받는지, 저널 저장 실패나 실행·수신자 불일치 시 계획을 반환하지 않는지 검사한다.
- [x] 3.2 `push-inbox`, `push-observe`, `push-ack`에 소유자 검사를 적용한다. 상대 채팅의 사건 ID를 직접 지정해도 조회·관찰·확인 처리할 수 없는지 검사한다.
- [x] 3.3 관리 승인 훅을 `journal-approval` 명령 하나로 갱신한다. 기존 관리 그룹의 `mcp_tool`이 제거되고, 사용자 훅과 Desktop 신뢰 설정은 유지되는지 검사한다.
- [x] 3.4 개발 소스의 컨트롤러·워커 지침을 갱신한다. 지침에 현재 채팅 등록, 실행 수신자 확인, 종료 결과의 기록 순서와 다음 턴의 승인 조회가 모두 있는지 확인한다.
- [x] 3.5 종료 결과의 수신자와 원본 사용자 메시지를 대조하는 절차를 작업 지시와 워커 스킬에 추가한다. Desktop 어댑터 검사에서 이 절차가 푸시 배정에만 포함되는지 확인한다.
- [x] 3.6 종료 결과의 일회성 허가를 실행에 저장한다. 같은 실행을 동시에 발행해도 전송 계획이 한 번만 나오고 배정한 채팅만 결과를 처리하는지 검사한다.
- [x] 3.7 결과 채택 시 프로젝트 단위 위임 또는 현재 실행의 허가로 워커 보관을 계획한다. 유지 요청, 허가가 없는 실행, 보관 응답 및 다음 실행의 허가 범위를 검사한다.

## 4. 통합 검증

- [x] 4.1 Worker Orchestrator 패키지 테스트와 루트 `npm test`를 실행한다. 검증용 패키지 검사를 통과하고 공개 배포 파일의 해시가 작업 전과 같은지 확인한다.
- [x] 4.2 같은 Desktop 프로젝트의 두 채팅에서 `0.1.7-local.3`으로 워커를 배정한다. 각 워커의 종료 결과가 자신을 배정한 유휴 채팅에서 새 턴을 시작하는지 확인한다.
- [x] 4.3 사용자가 직접 요청한 채팅에서 워커를 배정한다. 워커의 원본 허가 확인, Desktop의 전송 판단, 유휴 컨트롤러에서 실제로 시작된 턴을 각각 확인한다.
- [x] 4.4 일회성 결과 전송만 허가한 컨트롤러의 유휴 채팅이 Desktop에서 종료 결과를 받아 새 턴을 시작하는지 확인한다.
- [ ] 4.5 워커 채팅의 Desktop 승인 UI에서 승인 요청을 확인한다. 실행을 배정한 채팅의 다음 턴에서 같은 승인 사건을 조회한다.
  - `0.1.7-local.5`에서 실제 Desktop 승인 요청을 저널에 기록했다. 배정한 채팅의 다음 턴에서 동일한 사건과 워커 턴을 조회했고, 이미 끝난 승인으로 판정했다. 사용자 응답을 기다리는 승인 화면은 관찰하지 못했다.
- [x] 4.6 Desktop에서 보관을 명시적으로 허가한 실행을 검증하고 채택한다. 배정한 컨트롤러가 실제 보관 응답을 기록하고 워커가 보관 상태로 표시되는지 확인한다.
  - `0.1.7-local.5`에서 일반 워커의 결과를 채택했다. Desktop의 `archived: true` 응답을 기록한 뒤 같은 채팅을 Desktop 보관 목록에서 확인했다.
