# 실행을 배정한 채팅이 컨트롤러를 맡는다

## Why

현재 Worker Orchestrator는 프로젝트마다 컨트롤러 채팅 하나를 지정한다.
같은 Desktop 프로젝트의 여러 채팅에서 작업을 배정하려면 각 실행의 결과를 그 실행을 배정한 채팅으로 돌려보내야 한다.

## What Changes

- 공식 Desktop 프로젝트 목록과 채팅 이력으로 현재 채팅의 소속을 확인한다. 워커로 등록되지 않은 채팅은 확인 후 자동으로 등록한다.
- 새 채팅의 운영 권한은 모두 `false`로 시작한다. 사용자 위임은 채팅별로 기록한다.
- 배정할 때 실행에 컨트롤러 채팅을 기록한다. 컨트롤러는 자신이 맡은 작업과 현재 실행만 조회하고 처리한다.
- 소유자 기록이 없는 기존 실행은 기존 프로젝트 컨트롤러에게 속한다. 같은 작업의 후속 실행도 기존 소유자에게 속한다.
- 워커는 종료 결과를 저널에 저장한 뒤, 등록된 실행에서 찾은 컨트롤러에게 기존 Desktop 메시지 도구로 후속 메시지를 보낸다.
- **BREAKING** 보관을 허가받고 후속 배정이 없는 워커는 검증한 결과를 채택할 때 보관한다. 사용자가 워커 유지를 요청하거나 후속 배정을 정했으면 유지한다.
- **BREAKING** 승인 훅은 저널에만 기록한다. 컨트롤러는 다음 턴에서 승인 사건을 조회한다. 사용자는 기존 Desktop 승인 UI에서 응답한다.

### New Capabilities

### Modified Capabilities

- `worker-project-control` — 현재 채팅의 자동 등록, 채팅별 위임, 실행 한 건의 보관 허가, 소유자별 상태 조회.
- `worker-run-lifecycle` — 실행 소유자 확인과 채택 후 워커 보관.
- `worker-event-delivery` — 저널 사건의 소유자 확인, 종료 결과의 후속 메시지, 승인 훅의 기록 범위.

## Impact

Worker Orchestrator의 Desktop 어댑터, 로컬 CLI와 상태 저장소, 컨트롤러·워커 워크플로가 대상이다.
공개 명세와 배포본은 현재 배포 상태의 기준으로 사용한다.
