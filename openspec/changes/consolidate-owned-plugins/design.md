# Design

## Context

Personal Harness는 각 PC에서 제공하는 번들을 등록하고 설치한다.
자체 플러그인의 소스는 각 원본 작업 트리에서 관리해 왔다.

## Goals / Non-Goals

**Goals**

- 세 원본 스레드에서 받은 인수본의 커밋과 체크섬을 확인한다.
- 플러그인별 구현, 스킬, 훅, 공용 참조, 패키징과 테스트를 한 저장소에 둔다.
- 각 플러그인의 배포본을 이관된 소스에서 다시 만들 수 있게 한다.

**Non-Goals**

- PC의 설치, 권한과 작업 상태는 각 PC에서 관리한다.
- 새 번들 게시와 기존 설치 경로 전환은 별도 작업이다.

## Decisions

`plugins/<이름>/`을 각 플러그인의 소스 루트로 사용한다.
패키지가 실행에 사용하는 공용 매니페스트, 템플릿과 의존성 선언을 이관한다.
공용 소스는 공개 GitHub `main`에서 관리한다.
원본의 작업용 지침과 PC별 경로, 개인·조직별 설정과 제품별 설정은 해당 환경에 둔다.
이관한 소스의 버전과 출처 커밋을 기록한다.
설치기는 기존에 게시한 번들의 `version`과 `bundle_sha256` 고정값을 사용한다.

## Risks / Trade-offs

패키징 스크립트가 단독 저장소 경로를 전제할 수 있다.
이관한 위치에서 패키지를 만들고 원본 스레드의 검증 결과와 대조한다.
repo-governance의 번들 검사는 플러그인 소스를 포함하는 Git 작업트리의 제외 규칙을 확인한다.
