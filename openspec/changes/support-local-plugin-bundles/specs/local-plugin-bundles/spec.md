# Spec Delta

## Purpose

PC마다 받은 Codex 배포본의 파일을 검증한 뒤 같은 플러그인을 설치한다.
배포본의 위치는 해당 PC의 로컬 설정에서 지정한다.

## ADDED Requirements

### Requirement: Pinned local plugin bundles

등록 목록은 로컬 번들의 플러그인 이름, 마켓플레이스 이름, 정확한 버전과 SHA-256을 고정해야 한다(MUST).
설치기는 PC별 설정에서 지정한 번들의 내용과 식별자를 검증해야 한다.

#### Scenario: 자체 플러그인 소스만 이관한 경우

- **WHEN** Personal Harness가 자체 플러그인 소스를 `plugins/`에 추가한다.
- **THEN** 설치기는 이미 게시한 번들의 정확한 버전과 SHA-256 고정값을 사용한다.

#### Scenario: 호스트 경로가 설정되지 않은 경우

- **WHEN** PC의 로컬 설정에 해당 마켓플레이스 경로가 없다.
- **THEN** 설치기는 기존 등록을 보존하고 다른 의존성 설치를 진행한다.

#### Scenario: 잘못된 번들 경로 또는 내용으로 설치하려는 경우

- **WHEN** 지정한 폴더, 플러그인 식별자, 버전 또는 번들 체크섬이 유효하지 않다.
- **THEN** 설치기는 설치 작업을 시작하기 전에 오류를 보고한다.

### Requirement: Reproducible Codex installation

설치기는 검증한 로컬 번들을 Codex CLI로 등록해야 한다(MUST).
설치기는 실제 캐시 내용이 번들에서 선택한 플러그인과 일치하는지 검증해야 한다.
적용 계획과 점검은 같은 버전과 배포 경로의 설치 상태를 확인해야 한다.

#### Scenario: 설치 또는 재실행

- **WHEN** PC에 검증한 번들 경로가 설정되어 있고 `task install`을 실행한다.
- **THEN** Codex는 그 폴더를 출처로 등록하고 고정한 플러그인을 설치한다.
- **AND** 같은 출처와 설치 캐시가 확인되면 재실행에서 해당 마켓플레이스의 설치 작업은 생략된다.

#### Scenario: 이미 설치한 마켓플레이스에 다른 플러그인도 있는 경우

- **WHEN** 로컬 번들의 새 경로로 바꾸려면 다른 관리 주체의 마켓플레이스 또는 플러그인 등록을 제거해야 한다.
- **THEN** 설치기는 충돌을 보고하고 해당 등록을 보존한다.

#### Scenario: 로컬 번들의 적용 계획을 확인하는 경우

- **WHEN** PC별 번들 경로를 설정하고 `task plan` 또는 `task check`를 실행한다.
- **THEN** 하네스는 등록 출처와 설치 캐시를 읽어서 일치 여부를 보고한다.

#### Scenario: 이전 설치 릴리스에서 원격 갱신하는 경우

- **WHEN** `installer` 레이아웃을 사용한 이전 릴리스가 `package.json`의 `files`에 `sources`를 포함하고 설치 내용이 검증을 통과한다.
- **THEN** 원격 갱신은 그 릴리스를 이전 설치본으로 처리하고 기존 PC별 상태를 사용한다.
