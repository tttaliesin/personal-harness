# Design

## Context

프로젝트는 Git 기반 Codex 플러그인의 등록, 릴리스 해석, 원본 해시 확인과 설치를 이미 지원한다.
Taste Skill은 같은 구조의 공식 Codex 플러그인과 자동 선택 가능한 `design-taste-frontend`를 제공한다.
현재 원본의 일부 기본값은 기존 앱의 렌더링 방식과 충돌할 수 있다.

## Goals / Non-Goals

**Goals:**
원본 전체를 설치하고 모델이 사이트·디자인 작업에 맞게 선택하게 한다.
기존 앱의 프레임워크와 동작을 보존하는 경계를 공통 사용자 지침에 둔다.

**Non-Goals:**
원본 스킬 수정, 새 디자인 페이지 제작, 기존 프로젝트 구조 변경과 repo-governance 변경은 포함하지 않는다.

## Decisions

### 공식 플러그인 등록 재사용

`packages/harness/resources/registry.toml`에 공식 GitHub 저장소와 `.codex-plugin/plugin.json`을 등록한다.
최신 안정 릴리스를 정확한 commit으로 해석하고 전체 파일 해시를 기록한다.
별도의 스킬 복사 경로나 wrapper를 추가하지 않는다.

### 원본과 사용 경계 분리

플러그인의 스킬·참조·에셋은 수정하지 않는다.
사용자 지침은 사이트 제작과 시각 디자인에서 자연어 요청에 따라 선택하게 한다.
기존 프로젝트의 스택, SSR·API·인증, 컴포넌트·디자인 토큰과 배포 경로를 우선한다.
Sites의 호스팅 선택과 Taste의 디자인 선택은 각 작업 목적에 따른다.

### 범위를 제한한 실제 적용

두 PC에서 Taste 플러그인과 관련 등록만 추가한다.
현재 lock의 다른 도구 버전과 로컬 덮어쓰기를 유지한다.
공통 지침은 기존 적용기의 백업과 반복 적용 검사를 사용한다.
기존 설정에서 Taste 등록을 제외한 값과 repo-governance 파일 해시를 비교한다.

## Risks / Trade-offs

자동 선택 가능 상태는 모델이 모든 디자인 요청에서 반드시 스킬을 고른다는 보장이 아니다.
실제 시각 품질과 완료 시간 개선은 이번 설치 검증으로 주장하지 않는다.
원본 스크립트의 브라우저 사용 가능 여부는 두 PC의 실제 설치 환경에서 확인한다.
Codex용 자동 hook 등록 경로가 없으므로 별도의 hook 구성을 추가하지 않는다.

## Migration Plan

임시 프로필 설치에서 원본 전체 해시와 기존 설정 보존을 먼저 검증한다.
두 PC에 적용한 뒤 원본 해시, 활성 상태, 지침 일치와 남은 변경을 확인한다.
기존 설정과 적용 백업을 복구할 수 있게 유지한다.
