# Design

## Context

Codex의 로컬 마켓플레이스는 배포 폴더의 경로를 프로필에 기록한다.
기존 의존성 lock은 조회한 Git 플러그인과 MCP의 해석 결과를 저장한다.
로컬 번들은 등록 목록에 직접 고정한 값으로 검증할 수 있다.

## Goals

- 각 PC의 배포 경로에서 같은 로컬 플러그인 설치를 재현한다.
- 일치하는 설치본을 재사용하고, 같은 이름의 다른 플러그인 등록을 보존한다.

## Decisions

`packages/harness/resources/registry.toml`의 `[[local_plugins]]`에 이름, 마켓플레이스 이름, 버전, `bundle_sha256`과 활성 상태를 기록한다.
이전 로컬 번들의 `source_path`는 이관 당시의 소스 경로인 `plugins/<이름>`을 기록한다.
공개 Git 마켓플레이스 배포 경로는 루트 카탈로그의 `source.path`에서 관리한다.
설치기는 이미 게시한 배포본의 버전과 SHA-256 고정값을 사용한다.
기존 의존성 lock의 Git 및 MCP 등록은 기존 방식으로 관리한다.
상대 배포 경로는 로컬 설정 파일이 있는 폴더에서 해석한다.
로컬 설정의 `[plugin_bundles]`에서 마켓플레이스 이름별 경로를 지정한다.

번들 체크섬은 폴더의 파일별 SHA-256을 경로 순서로 정렬한 JSON의 SHA-256이다.
마켓플레이스 정의에는 해당 플러그인의 로컬 설치 경로가 있어야 한다.
설치기는 검증한 폴더를 CLI에 넘기고, 선택한 플러그인 하위 폴더의 체크섬을 설치 캐시와 비교한다.

설치기는 같은 출처가 등록되어 있으면 필요한 플러그인만 갱신한다.
다른 출처를 등록하기 위해 기존 마켓플레이스를 교체할 때에는 관리하는 플러그인의 기존 선택을 보존한다.
등록이나 설치가 실패하면 이전 마켓플레이스 등록을 복구할 수 있는 범위에서 되돌린다.
`task plan`, `task check`, `task apply`는 지정한 번들과 기존 설치 상태를 읽고, `task install`이 설치 작업을 수행한다.

원격 갱신에서는 `installer` 레이아웃의 이전 릴리스가 선언했던 `sources` 항목을 이전 릴리스 검증에 허용한다.

## Risks / Trade-offs

Codex는 설치 이후에도 로컬 마켓플레이스 경로를 사용하므로 배포본은 지속적으로 쓸 수 있는 위치에 둔다.
동일한 버전의 파일이 바뀌면 등록 목록의 체크섬과 설치 캐시를 함께 검증한다.
