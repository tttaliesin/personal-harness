# Context7 설치와 문서 조회 확인

2026년 11월 17일 Homelab Desktop과 Roylabs Desktop에 공식 Context7을 설치했다.
사용자 요청은 두 PC 설치, 필요시 자율 선택, 공통 등록·지침 반영과 main 커밋·푸시다.

## 설치 원본

| 항목 | 확인 값 |
|---|---|
| 플러그인 | `context7@context7-marketplace` |
| 출처 | [upstash/context7](https://github.com/upstash/context7) |
| Manifest | `plugins/codex/context7/.codex-plugin/plugin.json` |
| 플러그인 버전 | `1.0.2` |
| 고정 commit | `27ef14ca41a57563891135cad663732d43203a8b` |
| 원본 콘텐츠 SHA256 | `ff7c6095e8effa93b876fc2f326dd21b7784063f034be7ce1b5fd56b72ea1fdd` |
| 갱신 기준 | registry의 `git-ref: master`를 설치 시 정확한 commit으로 해석 |
| MCP endpoint | `https://mcp.context7.com/mcp` |

모노레포의 CLI·MCP 패키지 릴리스 번호와 플러그인 버전은 별개다.
공식 Codex CLI와 기존 플러그인 설치기를 사용했다.
플러그인의 스킬과 MCP 설정은 원본 그대로 유지했다.
동일한 MCP를 별도로 중복 등록하지 않았다.

## 실제 적용 결과

| 확인 대상 | Homelab | Roylabs |
|---|---|---|
| 공식 플러그인 설치와 원본 digest | 일치 | 일치 |
| Context7 등록을 제외한 기존 설정 | 동일 | 동일 |
| root task apply/check | 성공, 잔여 변경·누락 0개 | 성공, 잔여 변경·누락 0개 |
| `initialize`와 `tools/list` | HTTP 200 | HTTP 200 |
| `resolve-library-id` | 오류 없이 Python 공식 원본 식별 | 오류 없이 Python 공식 원본 식별 |
| `query-docs` | 오류 없이 pathlib 문서 반환 | 오류 없이 pathlib 문서 반환 |

두 PC는 각자의 기존 PersonalHarness 상태 경로를 사용했다.
적용 계획은 사용자 AGENTS.md 한 파일의 변경만 포함했다.
공통 지침의 실제 파일 SHA256은 두 PC 모두 `9fbf483e688895ac5b7964f38ba28cf9d4d36d74ce48d931b17e290bf3b2ffb9`였다.
기존 agent-desktop·CodeGraph·OpenSpec·Taste 버전은 유지했다.
Roylabs의 repo-governance 설치 경로에서 확인한 파일 80개의 해시가 설치·적용 전후 동일했다.
기존 hook 선언과 신뢰 상태를 포함한 설정 값도 유지했다.
repo-governance 개발 소스에는 변경 작업을 수행하지 않았다.

## 자율 선택과 확인 범위

공통 지침은 실제 의존성 버전을 확인한 뒤 문서가 필요한 작업에서 Context7을 선택하도록 한다.
스킬 이름이나 별도 호출 문구가 필요하지 않다.
직접 파일 읽기·정확한 검색·작은 기계적 수정에는 선행 조건을 추가하지 않는다.
서비스가 실패하거나 해당 버전이 없으면 공식 문서·소스·로컬 검사로 계속한다.
비공개 코드·인증 값·대화 전체의 전달과 요청하지 않은 평가·피드백 전송을 지시하지 않는다.

설치 뒤 현재 Codex 대화에 두 도구가 노출됐으며 실제 MCP 도구 호출로 식별과 문서 조회를 확인했다.
Roylabs의 별도 기존 Desktop 대화가 갱신됐는지는 검증하지 않았다.
새 스레드 로딩은 [공식 설치 안내](https://context7.com/docs/clients/codex)를 따른다.
모델의 일반 작업별 선택률이나 개발 속도·정답률 향상은 측정하지 않았다.

이번 두 PC의 프로토콜 검증은 인증 정보를 제공하지 않은 상태에서 성공했다.
응답 서버 버전은 `4.7.0`이며 도구는 `resolve-library-id`와 `query-docs`였다.
이 관찰은 향후에도 무인증 접근이 유지된다는 보장이 아니다.
계정·인증·세션 정보는 Git에 추가하지 않았다.

## 저장소 검증

공식 원본을 임시 Codex 프로필에 먼저 설치해 digest와 기존 설정 보존을 확인했다.
`task test`는 285개 테스트를 실행해 실패 없이 끝났다.
그중 2개는 환경 조건으로 생략됐다.
OpenSpec strict validation은 issue가 없다고 반환했다.
두 PC의 실제 적용은 임시 프로필 테스트와 별도로 실행했다.
