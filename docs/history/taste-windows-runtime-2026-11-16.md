# Taste Windows 브라우저 실행 호환 적용

2026년 11월 16일 `taste-windows-runtime`을 두 PC에 적용했다.
원본 Taste 2.5.1 게이트의 브라우저 실행 오류를 해소했고 같은 문장노트 페이지에서 실제 검사 결과를 얻었다.
페이지 판정은 두 PC 모두 `GATE: FAIL 41`이며 경고는 14건이다.

## 원인과 재현

원본 `assets/layout/check.mjs`의 기본 브라우저 목록에는 Windows Edge가 없다.
Chrome이 없는 두 PC에서 브라우저 경로를 명시하지 않으면 해당 검사를 실행할 수 없다.

원본 `consistency.mjs`는 런처의 exit 이벤트를 즉시 시작 실패로 처리한다.
Homelab의 별도 프로필에서는 플래그 없이 실행한 Edge 런처가 64ms 후 코드 0으로 끝났다.
그 시점에는 CDP 포트 파일이나 stderr의 준비 신호가 없었다.
`--edge-skip-compat-layer-relaunch`를 넣은 실행은 런처가 유지되며 312ms에 CDP 포트 파일과 stderr 준비 신호를 반환했다.
각 조건은 1회 관측이며 시간 차이는 성능 순위나 일반적인 속도 개선의 증거가 아니다.

Roylabs의 raw Edge 실행은 두 조건 모두 시작에 성공했다.
따라서 런처 현상을 모든 Windows PC에서 발생하는 문제로 일반화하지 않는다.
고정한 페이지와 원본 버전에서 실제 게이트가 완료되는지를 최종 성공 조건으로 삼았다.

## 실행 호환의 범위

저장소 소유 실행기는 원본 `.mjs`와 인수를 그대로 Node 자식 프로세스에 전달한다.
기존 `CHROME_PATH`를 우선하며 없으면 설치된 Chrome 또는 Edge를 찾는다.
선택한 브라우저 경로와 preload는 해당 자식의 환경에만 설정한다.
기존 `NODE_OPTIONS`와 다른 환경값은 보존한다.

```mermaid
flowchart LR
    A[기존 Taste 검사 명령] --> B[저장소 소유 실행기]
    B --> C[자식 프로세스의 브라우저 경로]
    C --> D[원본 게이트와 검사기]
    D --> E[선택된 headless Edge 실행 보정]
    E --> F[원본 판정과 종료 코드 반환]
```

preload는 선택된 Edge 경로의 headless spawn에만 재실행 방지 플래그를 추가한다.
다른 실행 파일, Chrome, 비 headless Edge와 `spawnSync`는 변경하지 않는다.
Windows 중단은 전용 IPC로 원본 신호 핸들러에 전달한다.
원본이 10초간 응답하지 않을 때만 자체 자식 프로세스 계열을 종료한다.
일반 실행의 원본 숫자 종료 코드를 그대로 반환한다.

원본 플러그인·캐시, 페이지의 kit, repo-governance, hook과 전역 환경변수는 편집하지 않았다.
기존 Taste 검사와 판정에 waiver를 추가하지 않았다.

## 실제 두 PC 검증

| 항목 | Homelab Desktop | Roylabs Desktop |
|---|---:|---:|
| Node | 24.18.1 | 22.23.3 |
| 실행기·지침 적용 | 완료 | 완료 |
| 동일 정적 파일 | 1,600개 | 1,600개 |
| 게이트 결과 재사용 | 없음 | 없음 |
| 브라우저 검사 오류 | 0 | 0 |
| 원본 게이트 페이지 판정 | FAIL 41 | FAIL 41 |
| 원본 경고 | 14 | 14 |
| 원본 종료 코드 | 1 | 1 |
| 보존 대상 파일 | 1,694개 | 1,774개 |
| 보존 대상 변경 | 0 | 0 |

두 PC의 실행기 4개 파일과 공통 지침 SHA256이 일치했다.
검증 페이지의 HTML·CSS·JavaScript와 정적 자산은 실행 전후 바이트가 같았다.
이전 `gate.json`이 없는 새 임시 폴더에서 각각 실행했다.
원본 판정의 `crashed` 목록이 비었고 결과 재사용이 false임을 확인했다.
Homelab의 최종 `task check`는 변경 0개·누락 의존성 0개였다.

페이지 문제에는 제품 UI의 겹침, 낮은 대비, 제목 크기와 가장자리 규칙 등이 포함됐다.
기존 독립 검사 18조건 통과는 가로 넘침·서체·동작·fallback의 제한된 확인이었다.
그 검사는 Taste 전체 디자인 검사 통과를 의미하지 않는다.
이번 변경은 같은 페이지로 런타임을 검증하는 범위이므로 페이지를 고치거나 실패를 숨기지 않았다.

## 테스트와 한계

설치기 변경을 포함한 `task test`는 284개 테스트를 성공적으로 실행했으며 2개는 환경 조건에 따라 건너뛰었다.
이후 보완한 종료 처리는 최종 실행기 경계 테스트 4개로 별도 확인했다.
최종 설치기 테스트 66개도 성공했으며 1개는 환경 조건에 따라 건너뛰었다.
한글·공백·빈 문자열 인수, 기존 Node 옵션, 종료 코드 42와 취소 시 원본 정리·종료 코드 29의 보존을 검증했다.
스킬 validator와 OpenSpec strict validation도 통과했다.

런타임은 두 PC의 해당 Node·Edge 조합에서 검증했다.
다른 브라우저·Taste 버전의 모든 실행 조합이나 강제 OS 종료 이후 정리까지 보장하지 않는다.
같은 원본과 페이지에서 실행기를 통해 게이트를 실행해 재현한다.
브라우저 검사 오류가 재발하거나 원본·페이지 해시가 바뀌면 이 변경의 성공 조건은 충족되지 않는다.
