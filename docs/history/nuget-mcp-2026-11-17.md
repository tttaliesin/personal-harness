# 공식 NuGet MCP 두 PC 적용

2026년 11월 17일 사용자 요청으로 공식 NuGet MCP를 두 PC에 추가했다.
C# 패키지 작업에서 필요한 경우 자율적으로 선택하도록 공통 지침을 배포했다.
기존 프로젝트의 .NET 선언과 repo-governance는 보존했다.

## 배포 구성

| 항목 | 확인 값 |
|---|---|
| 등록 이름 | `nuget` |
| 원본 패키지 | Microsoft `NuGet.Mcp.Server` `1.4.23` |
| 플랫폼 패키지 | `NuGet.Mcp.Server.win-x64` `1.4.23` |
| 실행 대상 | 원본 `tools/net10.0/win-x64/NuGet.Mcp.Server.dll` |
| 전용 SDK | 공식 .NET `10.0.404`, 포함된 Core·ASP.NET Core 런타임 `10.0.15` |
| 연결 | 전용 SDK의 `dotnet exec`를 통한 stdio |
| MCP 프로토콜 | `2025-03-26` |
| 서버의 응답 이름·어셈블리 버전 | `NuGet.Mcp.Server`, `1.0.0.0` |
| 등록 fingerprint | `0df846381c3f401da73459738c7789c4ee5169a8ab50d2da1b0af3edf29f8727` |

패키지 버전과 서버가 응답한 어셈블리 버전은 구분한다.
현재 Desktop 대화의 실제 `get_latest_package_version` 호출로 원본 패키지의 최신 안정 버전 `1.4.23`도 확인했다.

공식 출처는 [NuGet 패키지](https://www.nuget.org/packages/NuGet.Mcp.Server/1.4.23), [사용 문서](https://learn.microsoft.com/en-us/nuget/concepts/nuget-mcp-server), [Microsoft .NET 10 배포 메타데이터](https://dotnetcli.blob.core.windows.net/dotnet/release-metadata/10.0/releases.json)다.
SDK ZIP은 배포 메타데이터의 SHA512로 검사한다.
기본·플랫폼 NuGet 패키지는 공식 HTTPS 원본에서 관찰한 SHA512와 전체 파일 SHA256을 lock에 기록한다.
이 무결성 검사는 NuGet 패키지 서명 검증과 구분한다.
lock에 원본 URL과 해시를 보관하며 SDK·서버 바이너리는 Git에 포함하지 않는다.

## 설치기와 지침

registry의 `nuget` 종류는 공식 NuGet MCP의 Windows x64 배포에 한정된 설치 어댑터로 연결한다.
선택 버전, 기본 패키지의 플랫폼 참조, 실제 실행 파일, .NET 10 공유 프레임워크 요구사항을 확인한다.
SDK와 원본 패키지는 하네스 상태의 관리 경로에 설치한다.
실행 중 변경되는 CLI 상태는 설치 영수증이 검사하는 불변 파일 디렉터리 밖에 둔다.
후속 검사에서 설치 파일의 추가·변경·삭제를 탐지한다.
`task share`도 NuGet 항목을 공식 NuGet 원본으로 검증하며 PyPI로 잘못 분류하지 않는다.

C# 패키지 추가·업데이트·버전·의존성·피드 작업에서 실제 정보가 필요할 때 명시적 호출 없이 선택한다.
작업과 관련된 프로젝트 파일·중앙 패키지 관리·lock·피드·SDK 선언을 확인한다.
Context7·Microsoft Learn과 고정 호출 순서를 두지 않는다.
모든 C# 수정의 필수 조회나 새로운 hook·승인 단계를 추가하지 않는다.
패키지 컨텍스트는 외부 참고 자료이며 사용자·저장소의 제약을 우선한다.
수정 도구는 허용된 작업 범위 안에서만 사용한다.

MCP 실행용 SDK가 대상 프로젝트의 SDK 요구사항을 충족한다는 뜻은 아니다.
프로젝트 그래프 평가에 필요한 SDK가 없으면 기존 선언을 바꾸지 않고 그 제한을 보고한다.

## 실제 두 PC 검증

| 검증 | Homelab | Roylabs |
|---|---|---|
| 설치 전 전역 상태 | .NET 설치 없음 | Core·Desktop 런타임 `10.0.10`, SDK 없음 |
| 전용 SDK·원본 설치 무결성 | 통과 | 통과 |
| root `task apply` | 설정·지침 두 파일 적용 | 설정·지침 두 파일 적용 |
| root `task check` | 잔여 파일·누락 0개 | 잔여 파일·누락 0개 |
| 실제 초기화·도구 조회 | 성공, 도구 6개 | 성공, 도구 6개 |
| 실제 안정 버전 조회 | Newtonsoft.Json `13.0.4` | Newtonsoft.Json `13.0.4` |
| .NET 8 임시 프로젝트 파일 | 해시 동일 | 해시 동일 |
| 실행 후 영수증 검사 | 통과 | 통과 |
| 기존 전역 .NET·PATH | 동일 | 동일 |
| NuGet 블록을 제외한 사용자 지침 | 동일 | 동일 |
| repo-governance 캐시 | 해당 경로 없음 | 84개 파일 해시 동일 |

두 PC의 적용된 사용자 지침 SHA256은 `b2633093f7f7e0901a22acc7e214a399b4cb64344985584df2047aefe27110fb`다.

제공 도구는 `get_latest_package_version`, `get_package_context`, `update_package_version`, `upgrade_packages_to_latest`, `fix_vulnerable_packages`, `review_supply_chain_security`다.
실제 검증에서는 버전 조회만 사용했다.
임시 프로젝트는 `net8.0`, SDK `8.0.414`, Newtonsoft.Json `13.0.3`과 공식 공개 피드를 선언했다.
조회 뒤 네 파일의 해시가 모두 동일했다.
실제 개발 저장소의 프로젝트 파일은 수정하지 않았다.

Homelab에서는 현재 Desktop 대화에도 도구가 노출되어 실제 MCP 호출을 완료했다.
이번 자동 선택 확인 범위는 공통 지침의 실제 배포와 사용 가능성 확인이다.
이름을 숨긴 새 Desktop 대화의 자동 선택률 실험은 수행하지 않았다.

Roylabs에는 공개 저장소의 정확한 구현 commit `0cbcd9f420e56f8da334149c1cf14a84716ed0d9`를 직접 내려받아 적용했다.
기존 다른 도구·플러그인의 버전과 lock 기록은 유지했다.
최초 진단 시점과 NuGet 적용 직전 백업 사이에는 기존 설정의 해시 변화가 관찰됐다.
그 변화의 원인은 확정하지 않았다.
NuGet 적용 직전 백업과 최종 설정은 새 `mcp_servers.nuget`를 제외하면 동일했다.
기존 변화는 복원하거나 수정하지 않았다.

## 소스 검증과 정리

NuGet 전용 테스트 18개와 registry 테스트 14개가 통과했다.
설치기 전체 `task test`는 305개 실행·303개 통과·2개 환경 생략·실패 0개로 완료했다.
등록 공유 보완 뒤 해당 테스트 41개도 통과했다.
최종 소스의 전체 재검사는 306개 실행·304개 통과·2개 환경 생략·실패 0개로 완료했다.
처음 제한된 실행 환경에서 실패한 기존 하위 프로세스·로컬 패키지 서버 검사는 실행 권한이 허용된 환경에서 다시 확인했다.
OpenSpec strict 검사는 통과했다.

실제 프로필 적용 백업과 이전 의존성 lock 백업은 각 PC의 기존 관리 경로에 보관한다.
작업용 소스·진단·패키지 조회용 프로젝트는 두 PC에서 모두 정리했다.
인증·계정·세션·원격 프로필 내용과 실행 중인 파이프는 Git에 포함하지 않는다.
