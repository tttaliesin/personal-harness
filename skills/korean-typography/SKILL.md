# 한글 웹 타이포그래피

실제 한국어 문구가 읽기 좋고 제품의 인상에 맞게 보이도록 서체와 조판을 선택한다.
사용자의 요청과 기존 브랜드·디자인 시스템을 우선한다.
이 지침의 수치는 조정을 시작할 범위이며 표준이나 통과 조건이 아니다.

## 맥락과 서체 선택

- 결과물의 주 언어와 대상 독자를 확인한다.
  한국어로 받은 요청이 영문 사이트를 요구하면 그 사이트에 한글 서체를 강제하지 않는다.
- 기존 font-face, 폰트 파일, 토큰과 실제 사용 서체를 먼저 확인한다.
  브랜드 서체가 한글을 지원하면 유지하고 역할별 크기·굵기·행간을 조정한다.
  영문 전용 브랜드 서체는 유지하면서 조화로운 한글 서체를 연결할 수 있다.
- 새 서체가 필요하면 [서체 후보와 로딩 기준](references/fonts.md)을 읽고 제품의 인상과 용도에 맞게 선택한다.
  모든 페이지를 한 가지 고딕으로 통일하거나, 한글 제목에 명조를 일괄 금지하지 않는다.
- 본문은 한글·영문·숫자를 함께 다루는 패밀리를 우선 고려한다.
  다른 영문 서체를 섞을 때는 실제 글자 크기·굵기·기준선·숫자 폭을 확인한다.
  Latin-only 서체를 선언한 것만으로 한글 디자인이 정해졌다고 보지 않는다.
- `lang="ko"`를 한국어 문서나 해당 구간에 맞게 지정한다.
  다국어 화면은 언어별 폰트 토큰을 둘 수 있다.

## 크기·행간·자간

- 새 일반 UI의 본문은 16–18px, 단위 없는 line-height 1.5–1.8 정도에서 실제 밀도에 맞게 시작할 수 있다.
  촘촘한 표·작은 보조 정보와 긴 읽기용 본문은 각각 용도에 맞게 조정한다.
  기존 제품의 접근성 설정과 글자 확대를 유지한다.
- 여러 줄 한글 제목은 행간 1.2–1.4 정도에서 획의 밀도와 제목 크기를 보며 조정할 수 있다.
  라틴 대문자 제목의 작은 행간과 큰 음수 자간을 그대로 복사하지 않는다.
- 자간은 normal 또는 0에서 시작하고 실제 서체와 크기를 본 뒤 소폭 조정한다.
  같은 수치라도 한글과 영문에서 보이는 밀도가 다르므로 숫자만으로 평가하지 않는다.
- 제목·본문·버튼·설명·데이터의 역할이 굵기와 크기로 구별되게 한다.
  실제 제공하는 weight를 사용하고 브라우저의 합성 굵기·기울기를 의도한 서체로 오인하지 않는다.
  정렬이 필요한 수치 열에는 tabular-nums를 고려한다.

## 줄바꿈과 내용

- 한글은 글자 단위와 어절 단위 줄바꿈이 모두 가능하다.
  제목·버튼·짧은 소개 문구에는 keep-all을 먼저 고려하고, 좁은 열이나 긴 본문은 실제 줄 모양에 맞게 normal도 선택한다.
- keep-all을 쓸 때 긴 상품명·URL·영문 식별자가 넘치지 않게 overflow-wrap과 컨테이너의 최소 너비를 함께 다룬다.
  예시는 [적용 패턴](references/patterns.md)을 참고한다.
- 모바일에서 한두 글자만 남는 제목, 조사만 떨어지는 줄, 과도한 빈 줄과 잘린 받침을 확인한다.
  고정 `<br>`로 특정 화면만 맞추기 전에 제목 너비·글자 크기·문구를 조정한다.
  편집 의도가 있는 줄바꿈은 화면 크기별 결과를 확인해 사용할 수 있다.
- 영문의 단어 수·대문자·`ch` 기준을 한글 분량의 동일한 척도로 취급하지 않는다.
  실제 한국어 제목·버튼·본문으로 배치하며 영어 문장을 기계적으로 번역해 길이를 맞추지 않는다.

## 로딩과 다른 디자인 스킬

- 서체 이름뿐 아니라 배포 파일의 한글 범위, 필요한 weight와 라이선스를 확인한다.
  기존 프레임워크의 font loader·로컬 에셋·CSP·오프라인 요구를 유지한다.
  폰트가 필요한 프로젝트에서만 연결하고 OS 전체 서체를 설치하거나 전역 앱 설정을 바꾸지 않는다.
- 신뢰할 수 있는 원본의 WOFF2·공식 서브셋을 필요한 범위로 사용한다.
  CDN을 쓰면 버전을 고정하고 외부 로딩이 허용되는지 확인한다.
  전체 한글 패밀리나 모든 서브셋을 무조건 preload하지 않는다.
- fallback과 font-display는 읽기 가능성과 로딩 후 레이아웃 변화를 함께 보고 선택한다.
  알려진 문구만 넣은 축소 폰트는 사용자 이름·입력값 등 동적 한국어 전체를 지원하지 않을 수 있다.
- Taste Skill 같은 원본 패키지는 편집하지 않는다.
  실제 프로젝트의 폰트 토큰·스타일에서 한글 서체와 조판을 연결한다.
  영문용 기본값과 충돌하면 한국어 결과물의 요구를 우선하고, 검사를 속여 통과시키지 않는다.

## 실제 화면 확인

작업에 맞는 기존 브라우저 검증에서 한국어 문구와 혼합 문자열을 함께 확인한다.
예: `한글 화면을 또렷하게 읽습니다. 제품 Pro 2.0 · 10,000원 · ₩123,456 · 가나다라마바사`.
좁은 화면과 데스크톱에서 제목·본문·버튼·입력창·수치 열 및 로딩 전후 줄바꿈을 본다.
확대나 사용자의 텍스트 간격 조정으로 내용을 잘라내지 않게 한다.

computed font-family나 `document.fonts.check()` 성공만으로 한글이 그 폰트에서 그려졌다고 단정하지 않는다.
불확실하면 브라우저의 실제 rendered fonts 정보나 CDP의 글꼴별 glyph 사용 정보를 확인한다.
폰트 로딩을 막은 상태에서도 읽을 수 있는지 필요한 범위에서 확인한다.
새 검증 게이트를 추가하지 말고, 확인한 화면·서체·로딩 조건과 남은 한계를 보고한다.
